# Mod-Eight-Journal
Repo for storing finished projects and documenting any lessons

# Briefly summarize The Gaming Room client and their software requirements. Who was the client? What type of software did they want you to design?
- The client "The Gaming Room" wanted a game created called "Draw It or Lose It" that is a web-based game that hosts a server for users to connect to via their user client of the application. The application had to be able to support Windows, Mac, Linux, and mobile devices. 

# What did you do particularly well in developing this documentation?
- I feel the research and explanations comparing the benefits of each operating system as a client, server, or developing OS went the best.

# What about the process of working through a design document did you find helpful when developing the code?
- I appreciated the clear guidance and freedom of development environments was the most useful. Having a provided workspace and working on my own system allowed me to focus on coding more than figuring out mandatory IDEs. The design document gave information on what to do and this project's info was very specific and to the point.

# If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?
- I would probably revise and simplify the comparison table to fit a page better for readability.

# How did you interpret the user’s needs and implement them into your software design? Why is it so important to consider the user’s needs when designing?
- I focused the software design document on pointing out simple easy to follow solutions with additional options to allow the client to choose their own path with how to develop their application. Providing just one solution could lead to missed opportunities the client could pursue if I just gave too little information on alternatives.

# How did you approach designing software? What techniques or strategies would you use in the future to analyze and design a similar software application?
- The best technique I would use in the future is to give myself plenty of time to work through a problem. The provided Java code required very specific steps for Maven to work. I had to step away and start from scratch to get my "a ha" moment. Other then that I approached every task by doing exactly what was needed and left comments in the code with my initials to ensure other programmers who could also be using the code to know what was done.
